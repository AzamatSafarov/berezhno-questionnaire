# Передача доступа и запуск коллегой

## Владелец
1. Передать ZIP либо пригласить коллегу в приватный GitHub репозиторий (Settings → Collaborators). Ссылка на приватный репозиторий без приглашения не откроется.
2. Для текущей БД пригласить коллегу в Supabase organization/team, выдать минимально необходимую роль. Пароль автора не передавать. Учесть: доступ разработчика к БД может позволить читать чувствительные ответы.
3. Для публикации на текущий домен пригласить в Vercel project/team, если план позволяет. Альтернатива: коллега делает PR, владелец публикует.
4. Не передавать участницам ссылки разработчика и не включать реальный сбор без отдельного решения.

## Коллега
1. Распаковать ZIP или clone, открыть папку в своём Hermes.
2. Первым сообщением отправить: «Прочитай README.md и docs/STATUS.md, docs/BACKEND.md, docs/DEVELOPMENT-RULES.md. Запусти tests/test_browser.py. Сохраняй формулировки вопросов и не включай реальный сбор. Меняй только локальные файлы без публикации, пока я не разрешу».
3. Локальный сайт запускается по README без MCP и облачных разрешений.
4. Для управления БД при наличии собственного доступа подключить официальный Supabase MCP. Проверить актуальные docs: https://supabase.com/docs/guides/getting-started/mcp . Project-scoped endpoint: `https://mcp.supabase.com/mcp?project_ref=conpilbfsumopiddnzjj`. На первой настройке рекомендуется `&read_only=true`. Аутентификация через свою учётную запись; секреты не помещать в репозиторий.
5. Конфигурацию Hermes переносить только выборочно через его штатные команды/интерфейс, не копировать .hermes автора. Документация: https://hermes-agent.nousresearch.com/docs . MCP не предоставляет права, которых нет у аккаунта.
6. Любые SQL и деплой сначала тестировать в отдельной development среде.

## Репозиторий и публикация
GitHub не связан автоматически с текущим Vercel. Для отдельного сайта импортировать репозиторий в Vercel: framework Other, output public, build command пустой; vercel.json уже приложен. При смене Supabase update public/research-config.js и connect-src CSP в vercel.json.
Не коммитить `.vercel`, `supabase/.temp`, .env и токены. Не публиковать каталог целиком с docs как статический сайт — только public/.

## Почему не контейнер всего бэкенда
Бэкенд использует Supabase Auth, PostgreSQL, Realtime и облачную почту. Контейнер статических файлов не перенесёт эти настройки и доступы. Этот пакет даёт запускаемый frontend и SQL для отдельного Supabase, без копирования реальных записей. Для полноценного локального Supabase требуется Docker и Supabase CLI — этот вариант не протестирован на машине автора (Docker отсутствует).
