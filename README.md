# Berezhno — передача разработки

Статический сайт исследования: 10 методик, 240 вопросов, кабинет исследователя, Excel и Supabase RPC/Realtime.

## Начать за минуту

Установить Python (или uv), Git. Node.js нужен для проверки JS и Vercel CLI. Docker не требуется.

```bash
git clone https://github.com/AzamatSafarov/berezhno-questionnaire.git
cd berezhno-questionnaire
python -m http.server 8824 --bind 127.0.0.1 --directory public
```

Если `python` недоступен: `uv run python -m http.server 8824 --bind 127.0.0.1 --directory public`.
Открыть http://127.0.0.1:8824 . Без индивидуальной ссылки ответы остаются локальными, Supabase для разработки интерфейса не нужен.
Запустить Hermes **из корня этого репозитория**, либо открыть корень как проект в desktop. Инструкции для первой сессии Hermes находятся в docs/HANDOFF.md; передайте их агенту первым сообщением.

## Проверка

```bash
uv run --with playwright --with openpyxl python tests/test_browser.py
```

Если Chromium не установлен: `uv run --with playwright python -m playwright install chromium`. На Windows тест использует установленный Edge, если он доступен. Тест сам запускает локальный HTTP-сервер; синтетические ответы находятся только во временной папке.

## Бэкенд не находится на компьютере автора

Действующий бэкенд — управляемый Supabase `conpilbfsumopiddnzjj`, регион eu-west-1 (Ирландия). Публикация — Vercel `berezhno-questionnaire`, https://berezhno-questionnaire.vercel.app . Получение файлов не передаёт владение этими сервисами.

- Для изменения сайта достаточно репозитория и локального сервера.
- Для работы с текущей БД владелец приглашает коллегу в организацию Supabase с подходящей ролью. MCP подключается **под собственной учётной записью коллеги**; он не заменяет разрешения.
- Для публикации на текущий адрес нужен доступ к Vercel либо публикацию делает владелец. GitHub репозиторий создан для передачи, автоматический production deploy из него не подключён.
- Доступ разработчика к Supabase и разрешение исследователя в `research_admins` — разные права.
- Можно создать отдельный Supabase для разработки. Миграции приложены; **не применять их повторно к существующему production**.

Подробности: [BACKEND.md](docs/BACKEND.md), [HANDOFF.md](docs/HANDOFF.md), [STATUS.md](docs/STATUS.md).

## Что включено и исключено

Включены frontend/assets/vendor с исходными лицензиями, миграции и словарь вопросов, тесты и инструкции. В конфигурации frontend находится только публичный publishable key — он не даёт прав администратора.

Не включены ответы участниц, индивидуальные ссылки/токены, экспорт БД, пароли, SMTP-ключи, OAuth, личная конфигурация Hermes и `.vercel`-привязка аккаунта. Оригинальные документы согласия/контактов передаются отдельно владельцем по необходимости.

## Ограничения

Реальный сбор выключен. SMTP пока не настроен/не подтверждён, реальный почтовый вход после настройки redirect не подтверждён. Численно считается только MSPSS. При переносе проекта требуется проверить согласие, сроки хранения и настройки Auth. Полная проверка развёртывания БД на чистом Supabase в этом пакете не выполнена; см. STATUS.

Не публиковать репозиторий открыто без проверки прав на тексты методик и официальные изображения. Общая лицензия на весь проект не объявлена: лицензии vendor не лицензируют тексты опросников.
